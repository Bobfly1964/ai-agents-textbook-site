    Приложение Б. Словарь курса¶

    Рабочие формулировки из словарей глав 1–17 по алфавиту: сначала русские названия, затем латинские. В скобках — глава, где термин введён. Если поздняя глава уточняет формулировку ранней, приведены обе: «первое знакомство» и «уточнение». Точные определения и границы понятий — в самих главах.

    • Агентный цикл / agent loop — повторяющаяся последовательность «состояние → выбор действия → выполнение → observation → решение», где решение определяет продолжение или остановку (глава 2).
    • Вход — данные и условия, которые доступны задаче к моменту начала работы (глава 5).
    • Гипотеза — предположение о поведении системы, которое ещё предстоит проверить наблюдением (глава 16).
    • Действие / action — отдельный шаг системы в среде — например, вызов tool (глава 1).
    • Детерминированная операция — операция, которая при одинаковом входе и одинаковых заранее заданных правилах даёт один и тот же результат (глава 5).
    • Договор задачи (task contract) — согласованная и записанная до реализации постановка задачи: зачем выполняется работа, какие сведения даны, что должно получиться, что запрещено и как проверить готовность (глава 5).
    • ИИ-агент — система, в которой модель участвует в выборе следующего действия, а результат действия может повлиять на дальнейшие шаги (глава 1).
    • ИИ-приложение — программная система, которая обращается к модели и организует взаимодействие с пользователем, кодом, данными и внешними возможностями (глава 1).
    • Интерфейс — часть или способ взаимодействия с приложением: поле ввода, кнопка, экран результата или программный запрос (глава 1).
    • Контекст — информация, доступная модели в конкретном обращении (глава 1).
    • Критерий готовности — наблюдаемое условие, по которому команда может проверить, что требуемый результат получен в согласованной форме и не нарушает ограничения задачи (глава 5).
    • Наблюдение / observation
    • первое знакомство, глава 1: наблюдаемый результат действия, полученный из среды.
    • уточнение, глава 2: результат действия или обратная связь от среды, возвращённая в рабочий цикл.
    • Неопределённость — ситуация, в которой имеющихся данных или правил недостаточно, чтобы обоснованно получить один требуемый результат или выбрать один следующий шаг (глава 5).
    • Ограничение — правило, которое сужает допустимые способы выполнения задачи или запрещает определённые действия (глава 5).
    • Окно контекста / context window — ограниченный объём информации, который модель может использовать в конкретном вызове (глава 3).
    • Оркестрация / orchestration — программная логика, которая связывает этапы работы, маршрутизацию, вызовы и проверки (глава 3).
    • Память агента — не самостоятельный единый механизм, а общее слово, требующее уточнения; в зависимости от задачи могут использоваться состояние, Agent Skill, RAG, журнал, защищённая база и другие хранилища (глава 10).
    • Прогноз — ожидание будущего результата, записанное до наблюдения и сравниваемое с ним после (глава 16).
    • Результат — конкретный продукт или набор данных, который должен быть получен после выполнения задачи (глава 5).
    • Состояние / state
    • первое знакомство, глава 2: набор именованных полей с данными текущего запуска: шаги, отказы, последнее observation, пределы, признак завершения.
    • уточнение, глава 10: актуальные данные конкретной работы, необходимые для следующего шага или следующего запуска.
    • Среда — всё, с чем система взаимодействует при выполнении задачи и откуда получает результаты действий (глава 1).
    • терминал — результат, завершающий запуск: success, needs_input, error, limit (глава 2).
    • точка решения — момент сразу после observation, когда по нему и счётчикам выбирается continue или один из терминалов (глава 2).
    • Управление контекстом / context management — решение о том, что оставить в активном контексте, что сократить, записать во внешнее состояние или загрузить позже (глава 3).
    • Факт / наблюдаемый факт — утверждение, подтверждённое сохранённым артефактом: выводом команды, trace, файлом или тестом (глава 16).
    • Цель — польза от работы: какое изменение или решение должен поддержать итоговый результат (глава 5).
    • Цена ошибки — последствия, которые возникнут, если система примет неверный результат или выполнит неверное действие (глава 5).
    • Эвристика — правило выбора, которое обычно помогает, но не гарантирует результат и не является стандартом (глава 16).
    • Языковая модель / LLM — компонент, который получает доступный ему контекст и формирует результат (глава 1).
    • Agent Skill — переносимая процедура в каталоге, центральным обязательным файлом которой является SKILL.md; дополнительные ресурсы используются по необходимости (глава 4).
    • Allowlist / белый список — заранее определённый перечень разрешённых действий, имён или ресурсов (глава 7).
    • Approval event / событие подтверждения — event о наблюдаемом факте запроса, получения или отказа подтверждения; сам механизм и правила подтверждения в этой главе не определяются (глава 12).
    • Approval gate — техническая точка процесса, где дальнейшее действие блокируется до подтверждения человека (глава 14).
    • Arguments / аргументы — данные, которые передаются tool при конкретном вызове (глава 6).
    • Asset / защищаемый актив — данные, файлы, состояние или возможности, которым может быть причинён ущерб (глава 14).
    • assets/ — необязательная папка для шаблонов и других вспомогательных ресурсов (глава 9).
    • Baseline — зафиксированный исходный уровень поведения, с которым сравниваются изменения (глава 11).
    • Change proposal / предложение изменения — сформулированное изменение процедуры, которое ещё не является новой нормой (глава 13).
    • Checkpoint / контрольная точка состояния — сохранённое состояние, по которому работу можно продолжить после прерывания (глава 10).
    • Client — компонент на стороне host, который взаимодействует с конкретным MCP-сервером (глава 4).
    • Contract / контракт операции — согласованное описание назначения, входов, выхода, ограничений и ошибок операции (главы 5, 8).
    • Data minimization / минимизация данных — хранить и передавать только те данные, которые нужны следующему шагу или передаче работы (глава 10).
    • Dataset / набор случаев — заранее выбранный и зафиксированный набор test cases, на котором проводится Eval (глава 11).
    • Dependency / зависимость — внешний компонент (библиотека, пакет, сервис или файл), без которого наш код или skill не работает так, как задуман (глава 15).
    • Description trigger / описание-триггер — поле description в frontmatter, по которому решают, подходит ли процедура к текущей задаче, ещё до загрузки полных инструкций; слишком общее описание приводит к ложным и пропущенным вызовам, как у tool в главе 8 (глава 9).
    • Diff — наблюдаемое сравнение различий между двумя сохранёнными Version; показывает, что изменилось, но не оценивает качество поведения (глава 13).
    • Dispatch table / таблица соответствий — явное соответствие каждого разрешённого имени tool одной конкретной реализации; в starter — словарь AVAILABLE_TOOLS (глава 7).
    • Dispatcher / диспетчер — программный слой, который сопоставляет разрешённое имя tool с конкретной реализацией (глава 7).
    • Error case / ошибка — случай, проверяющий реакцию системы на некорректные входы, сбой операции или запрещённое действие (глава 8).
    • Eval — воспроизводимая оценка поведения системы на заранее определённом наборе случаев и критериев (глава 11).
    • Event / событие — одна наблюдаемая запись внутри Trace: что произошло, кем инициировано и с какими диагностическими полями связано (глава 12).
    • Event log / журнал событий — последовательный список наблюдаемых событий запуска: запрос tool, результат или ошибка, решение; каждый результат связан с id своего вызова (глава 7).
    • Exception / исключение — программная ошибка, возникшая во время уже начатого выполнения функции; приложение перехватывает её и превращает в наблюдаемый результат, а не в аварийную остановку (глава 7).
    • Failure point — первое наблюдаемое событие, после которого фактический маршрут перестаёт соответствовать ожидаемому для данного случая (глава 12).
    • Feedback / обратная связь — замечание, исправление или результат проверки, который может стать основанием для изменения процедуры (глава 13).
    • Frontmatter — структурированный блок метаданных в начале SKILL.md (глава 9).
    • Function calling / tool calling — механизм, при котором модель формирует структурированный запрос на использование доступной операции (глава 6).
    • Grader / проверяющий — человек или программа, которые применяют Rubric к результату и выносят решение «прошёл / не прошёл» (глава 11).
    • Handoff / передача работы — структурированная передача следующему исполнителю или запуску состояния, результатов и необходимых ограничений (главы 10, 16).
    • Harness / agent harness — программная среда вокруг модели, которая организует цикл, выполнение действий, состояние, ограничения, ошибки и взаимодействие с человеком (глава 3).
    • HITL / human in the loop — режим, в котором человек встроен в рабочий цикл и подтверждает определённые действия (глава 14).
    • Host — приложение или среда, внутри которой организуется работа MCP-подключений (глава 4).
    • HOTL / human on the loop — режим, в котором система действует более самостоятельно, а человек наблюдает и может вмешаться (глава 14).
    • Human approval / подтверждение человеком — явное решение человека, необходимое до выполнения определённого изменения (глава 14).
    • Indirect prompt injection — prompt injection, находящийся внутри внешнего материала — например документа или другого недоверенного содержимого (глава 15).
    • Inner loop — agent loop внутри одного запуска (глава 16).
    • JSON — текстовый формат представления структурированных данных (глава 6).
    • JSON Schema — способ формально описать ожидаемую структуру JSON-данных и допустимые значения (глава 6).
    • Least privilege / минимальные полномочия — предоставление только тех прав, которые действительно требуются для конкретной задачи (глава 14).
    • limit (предел) — заранее заданная граница числа действий; в этом демо — не более пяти (глава 2).
    • MCP / Model Context Protocol — протокол подключения ИИ-приложения к внешним системам, данным и возможностям через стандартизированное взаимодействие (глава 4).
    • Negative test / не должен — случай, в котором похожая ситуация не должна приводить к вызову данного действия (глава 8).
    • Observability / наблюдаемость — возможность понять поведение системы по журналам, traces, состоянию и проверкам (глава 12).
    • Outer loop — повторение отдельных запусков, каждый из которых продолжает работу по сохранённому внешнему состоянию (глава 16).
    • Owner / владелец решения — человек или явно определённая роль, несущая ответственность за итоговое решение (глава 16).
    • Pass rate — доля проверок, удовлетворивших заданным критериям (глава 11).
    • Permission scope / область разрешений — конкретный набор прав, который компонент запрашивает или получает, например «читать workspace» или «сеть к любому адресу»; не смешивать со Scope главы 8 — границей задачи tool (глава 15).
    • Permissions / разрешения — технически заданные права на чтение, запись, сеть, процессы или другие ресурсы (глава 3).
    • Positive test / должен — случай, в котором система должна выбрать или выполнить требуемое действие (глава 8).
    • Procedural experience / процедурный опыт — проверенное изменение повторяемой процедуры, которое можно перенести на будущие запуски (глава 13).
    • Procedural knowledge / процедурное знание — знание о том, как выполнять повторяемую работу; в курсе Agent Skill рассматривается как способ оформить такую процедуру (глава 10).
    • Progressive disclosure / постепенное раскрытие — подробности процедуры загружаются по мере необходимости, а не все одновременно (глава 4).
    • Prompt / инструкция — текстовая инструкция, передаваемая модели (глава 4).
    • Prompt injection — попытка через входной текст или данные заставить модель следовать инструкциям, конфликтующим с предусмотренной логикой системы (глава 15).
    • Provenance / происхождение — сведения о том, откуда получен код, skill, ресурс или зависимость; harness назначает provenance по каналу получения, а содержимое карточки остаётся untrusted_content (глава 15).
    • RAG / Retrieval-Augmented Generation — получение релевантных фактических материалов из внешнего поискового слоя и предоставление их модели (глава 10).
    • Read-only / только чтение — правило проекта: режим чтения используется по умолчанию, если изменение данных не является необходимым результатом текущего шага (глава 14).
    • references/ — необязательная папка для подробных справочных материалов, которые не нужно держать в основной инструкции постоянно (глава 9).
    • Regression / регрессия — ухудшение ранее работавшего поведения после изменения (глава 13).
    • Release candidate / кандидат на выпуск — версия проекта, готовая к итоговому прогону обязательных проверок перед защитой (глава 17).
    • Reproducibility / воспроизводимость — свойство проверки давать тот же результат при тех же случаях, критериях и условиях запуска (глава 11).
    • Resource / ресурс — доступный через интеграционный слой материал или источник данных (глава 4).
    • Resumable state / возобновляемое состояние — сохранённое вне процесса состояние, которого достаточно, чтобы новый запуск проверил, что уже сделано, и продолжил с явно записанного следующего шага (глава 16).
    • retry (повторная попытка) — разрешённая ещё одна попытка после сбоя; в этом демо — не более одной (глава 2).
    • Rollback / откат — возврат к предыдущей проверенной Version после неудачного изменения (глава 13).
    • Root cause / первопричина — первая существенная причина, из-за которой маршрут выполнения отклонился от ожидаемого (глава 12).
    • Rubric / рубрика — явный набор критериев оценивания наблюдаемого результата или поведения (глава 11).
    • Runtime / среда выполнения — часть программной среды, в которой фактически выполняются программы, функции или команды (глава 3).
    • Sandbox / изолированная среда — техническая среда, ограничивающая возможные последствия выполнения (глава 3).
    • Scope / граница задачи — ясное описание того, где задача tool начинается и заканчивается (глава 8).
    • scripts/ — необязательная папка для программ, необходимых процедуре (глава 9).
    • Secret / секрет — значение, дающее доступ к защищённому ресурсу, например API-токен; не хранится в обычном коде, SKILL.md, учебном репозитории или trace (глава 10).
    • Server — внешняя сторона MCP-подключения, предоставляющая доступные возможности (глава 4).
    • Session / сессия — один ограниченный по времени и контексту запуск работы системы (глава 16).
    • SKILL.md — основной обязательный файл Agent Skill, содержащий метаданные и инструкции процедуры (глава 9).
    • Structured output / структурированный вывод — требование вернуть результат в заранее определённой машинно-читаемой структуре (глава 4).
    • Subagent — отдельный ограниченный агентный запуск, которому передана конкретная подзадача и необходимый контекст (глава 16).
    • Supply chain / цепочка поставки — совокупность внешних компонентов и зависимостей, через которые в систему может попасть ошибочный или вредоносный код (глава 15).
    • Test case / тестовый случай — заранее заданная ситуация с ожидаемым наблюдаемым поведением (главы 8, 11).
    • Threat model / модель угроз — описание того, что нужно защитить, какие нежелательные события возможны и где проходят границы доверия (глава 14).
    • Tool / инструмент
    • первое знакомство, глава 1: конкретная операция, которую приложение умеет выполнять.
    • уточнение, глава 4: конкретная операция, доступная агентной системе.
    • Tool call — структурированное описание запрошенного вызова: имя операции и аргументы (глава 6).
    • Tool call record / запись Tool call — event, фиксирующий наблюдаемый Tool call с его call_id, именем и arguments; запись запроса не доказывает выполнение (глава 12).
    • Tool error / ошибка tool — структурированный результат неуспешного вызова: отклонение до выполнения (неизвестное имя, неверные arguments) или ошибка во время выполнения; не равен терминалу error всего запуска (глава 7).
    • Tool result — результат фактического выполнения tool, возвращённый в агентную систему (глава 6).
    • Trace / трассировка — последовательность наблюдаемых событий одного запуска; может включать вход, запрос tool, результат, ошибку, событие подтверждения и завершение; не включает скрытые рассуждения модели как обязательный учебный артефакт (глава 12).
    • Trust boundary / граница доверия — место, где данные, код или управление переходят между областями с разным уровнем доверия (глава 14).
    • Untrusted content / недоверенное содержимое — внешние данные, которым нельзя автоматически предоставлять статус системной инструкции (глава 15).
    • Validator / валидатор — проверка соответствия объекта заданным правилам до использования или принятия (глава 8).
    • Version / версия — идентифицируемое состояние процедуры или проекта, которое можно сравнить с другим (глава 13).
